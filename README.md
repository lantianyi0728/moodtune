# MoodTune 情绪电台

> 基于人脸情绪识别的歌曲推荐系统
> HTML5 + CSS3 + JavaScript + **Vue 3**

**在线体验**：<https://lantianyi0728.github.io/moodtune/>
（GitHub Pages 是 https，摄像头可直接使用；本地曲目首次加载会慢一些）

通过摄像头、本地图片、本地视频或拍照定格获取人脸，在**浏览器本地**用双通道算法识别 7 类情绪，
再按情绪的二维情感坐标与节奏特征推荐合适的歌曲。情绪识别全部在本地完成，画面不上传任何服务器。

---

## 一、快速开始

> ⚠️ **不能直接双击 `index.html`。**
>
> 用 `file://` 打开时，浏览器会以 CORS 策略**拦掉页面发出的所有本地请求**，
> 情绪模型（`models/*.json`）和曲库（`data/songs.json`）全都读不到，页面会提示「需要本地服务」；
> 摄像头 API 在 `file://` 下同样被禁用。
> 必须通过 `http://localhost:<端口>` 访问。

### 启动方式

| 方式 | 操作 | 说明 |
|---|---|---|
| **推荐** | 双击 `启动系统.vbs` | 后台静默启动，不弹黑窗口，自动打开浏览器 |
| 备用 | 双击 `start.bat` | 有可见窗口，能看报错；**窗口开着服务才在跑，别关** |
| 手动 | `node server.js` | 适合命令行用户 |

启动后浏览器会自动打开，地址形如 <http://localhost:8010/>。
端口被占用时会自动往后找（8010 → 8011 → …），不需要手动改。

如果双击 `index.html` 看到的是「请通过本地服务打开」，说明就是本文开头的情况：
先按上面任一种方式启动服务，再点页面上的「我已启动，进入系统」按钮即可跳过去。

> 服务器同时支持 **Range 请求**，否则音频拖动进度条、视频取元数据都会被卡住。

## 三、情绪识别算法（本地）

### 3.1 整体流程

```
画面帧
  │
  ├─ ① 人脸检测  TinyFaceDetector  ──►  多张人脸 + 置信度
  │         └─ 主角筛选：面积 × 中心贴近度 × 置信度（避免选到画面边缘被裁的脸）
  │
  ├─ ② 通道 A：CNN 表情分类   FaceExpressionNet ──►  7 类概率 P_cnn
  ├─ ③ 通道 B：68 点几何分析  ─────────────────►  7 类概率 P_geo
  │
  ├─ ④ 融合      P = w_cnn·P_cnn + w_geo·P_geo   （权重自适应）
  ├─ ⑤ 时间平滑  最近 14 帧指数加权平均
  ├─ ⑥ 迟滞锁定  主情绪切换需连续 3 帧且超阈值 18%
  │
  └─► 7 类概率 + 主情绪 + 置信度 + 情感坐标 (valence, arousal)
```

### 3.2 通道 A：CNN 表情分类

face-api.js 的 `FaceExpressionNet` 在人脸区域上做一次前向推理，
输出 7 类情绪的 **softmax 概率**：`neutral / happy / sad / angry / fearful / disgusted / surprised`。

选用它的原因：小模型（约 320 KB）、纯前端可跑、对人脸对齐不敏感。

但纯 CNN 有两个问题：**① 置信度会过度集中在 neutral**；② 遇到侧脸、遮挡时容易输出接近均匀分布的"糊"结果。
所以引入第二个通道。

### 3.3 通道 B：68 点几何特征分析

用 `faceLandmark68Net` 拿到 68 个关键点（iBUG 300-W 标准），先按人脸尺度归一化，再测量客观几何量：

尺度基准：`眼距` 与 `脸高 = |下巴(8) - 鼻梁顶(27)|`

| 特征 | 计算方式 | 情绪学含义 |
|---|---|---|
| 嘴角曲率 `mouthCurve` | `(唇中点Y - 嘴角Y) / 脸高`，正值为上扬 | 开心 / 悲伤 |
| 嘴巴张开度 `mouthOpen` | `|内唇下(66) - 内唇上(62)| / 脸高` | 惊讶、恐惧 |
| 嘴巴横向拉伸 `mouthWide` | `|嘴角右(54) - 嘴角左(48)| / 眼距` | 恐惧、开心 |
| 眉毛倾斜 `browSlant` | `(内眉Y - 外眉Y) / 脸高`，正值为皱眉 | 愤怒、厌恶 |
| 眉毛高度 `browRaise` | `(眼中心Y - 内眉Y) / 脸高` | 惊讶、恐惧 |
| 眼睛纵横比 `EAR` | `(2 条竖直眼睑距离) / (2 × 水平眼长)` | 眼睁大 / 眯眼 |
| 上唇上提 `upperLipRaise` | `(上唇(51)Y - 内唇上(62)Y) / 脸高` | 厌恶 |

每个特征用线性归一化 `ramp(x, lo, hi)` 映射到 `[0,1]`，再按情绪学规则加权求和，得到几何证据分。例如：

```
开心 = 0.62·ramp(mouthCurve, 0.002, 0.016)
     + 0.24·ramp(mouthOpen, 0.004, 0.05)
     + 0.14·ramp(mouthWide, 0.42, 0.62)

愤怒 = 0.46·ramp(browSlant, 0.003, 0.018)
     + 0.30·ramp(0.30 - EAR, 0, 0.09)      // 眼裂变窄
     + 0.24·ramp(-mouthCurve, 0.0005, 0.008)

平静 = 0.55 + 0.45·(1 - min(1, 其余 6 类峰值 × 2.2))
```

最后归一化成概率向量。**这套阈值是在真人脸样本上实测调出来的**（见 3.6 的验证数据）。

### 3.4 融合：为什么权重不是固定值

```
w_geo  = lerp(0.42, 0.18, ramp(max(P_cnn), 0.35, 0.85))
w_cnn  = 1 - w_geo
P      = w_cnn · P_cnn + w_geo · P_geo
```

- CNN **很自信**（最大概率接近 0.85）→ 更信 CNN（`w_geo = 0.18`）
- CNN **很含糊**（最大概率接近 0.35，典型于侧脸/遮挡）→ 几何证据补位（`w_geo = 0.42`）

界面左下角的「算法实时参数」面板会把**当前帧**的两路权重、检测置信度和全部几何量实时显示出来，
可以用来解释"这一帧为什么判成开心"。

### 3.5 时域处理：平滑 + 迟滞

摄像头逐帧推理必然有抖动，做两层处理：

**① 指数加权滑动平均**（窗口 14 帧）

```
P_t = Σ w_i · P_i / Σ w_i ,  w_i = exp(-age_i / 5)
```

**② 迟滞锁定（hysteresis）**

新情绪想"夺权"，必须同时满足：概率 > 当前主情绪 × 1.18，且 **连续 3 帧**成立。
否则维持原标签。这样情绪条不会在 49%/51% 之间来回横跳。

**注意**：单张图片 / 拍照定格属于单帧识别，**不走迟滞**，直接取最大概率——
否则会被上一次的锁定值拖住（这是开发中真实踩到并修掉的 bug）。

### 3.6 情绪 → 二维情感坐标

7 类概率加权映射到心理学常用的二维情感空间：

| 情绪 | valence（效价） | arousal（唤醒度） |
|---|---|---|
| 平静 neutral | 0.50 | 0.35 |
| 开心 happy | 0.92 | 0.76 |
| 悲伤 sad | 0.14 | 0.28 |
| 愤怒 angry | 0.22 | 0.94 |
| 恐惧 fearful | 0.16 | 0.72 |
| 厌恶 disgusted | 0.20 | 0.60 |
| 惊讶 surprised | 0.66 | 0.90 |

```
valence = Σ P_k · valence_k      arousal = Σ P_k · arousal_k
```

这两个连续值直接喂给推荐算法，避免了"7 个离散标签之间无法度量远近"的问题。

### 3.7 实测验证

用 face-api.js 官方示例剧照（生活大爆炸剧组，5 人同框）测试：

| 样本 | 识别结果 | 置信度 | valence | arousal | 单帧耗时 |
|---|---|---|---|---|---|
| bbt1.jpg | 平静 | 0.840 | 0.463 | 0.396 | — |
| bbt2.jpg | 平静 | 0.855 | 0.503 | 0.407 | — |
| bbt3.jpg | **开心** | 0.876 | 0.857 | 0.745 | 3.0 s |
| bbt4.jpg | **开心** | 0.879 | 0.862 | 0.752 | 3.0 s |

bbt3/bbt4 里人物在明显微笑，被正确判为开心（happy 单项概率 0.88）；其余两张表情平静，判为 neutral。
耗时是无 GPU 的无头浏览器数据；正常浏览器走 WebGL 后端会快一个数量级。

## 四、歌曲推荐算法

### 4.1 思路

把**情绪**和**歌曲**放进同一个二维情感空间（valence / arousal），情绪决定"目标坐标 + 目标 BPM 区间"，
歌曲按自身元数据计算贴合度。这样推荐结果可解释、可调试，而不是黑盒。

### 4.2 情绪画像表

| 情绪 | 目标 BPM 区间 | 目标 valence | 目标 arousal | 在线搜索关键词 |
|---|---|---|---|---|
| 开心 | 108–134 | 0.90 | 0.78 | happy upbeat pop / 开心 欢快 流行 |
| 悲伤 | 56–82 | 0.18 | 0.30 | sad piano emotional / 伤感 钢琴 慢歌 |
| 愤怒 | 132–165 | 0.24 | 0.92 | aggressive rock heavy / 愤怒 摇滚 燃 |
| 恐惧 | 68–96 | 0.20 | 0.62 | calm soothing ambient / 安静 治愈 舒缓 |
| 厌恶 | 92–120 | 0.26 | 0.58 | dark experimental electronic |
| 惊讶 | 118–142 | 0.68 | 0.88 | energetic electronic / 电子 燃 节奏 |
| 平静 | 76–100 | 0.52 | 0.38 | chill lofi instrumental / 轻音乐 |

> 恐惧和厌恶用的是**调节型**策略（给低唤醒、可预测的音乐来平复），
> 而不是同向加强——这是音乐治疗里的常见做法，代码里有注释说明。

### 4.3 评分公式

```
S = 0.40 · TagSim        情绪标签相似度
  + 0.25 · BpmFit        节奏贴合度
  + 0.20 · ValenceFit    效价贴合度
  + 0.15 · ArousalFit    唤醒度贴合度
  − Penalty              重复惩罚
  + Bonus                探索加分
```

各项定义：

```
TagSim      = TAG_SIM[用户情绪][歌曲标签]        // 9×9 相似度矩阵，同名 1.0
BpmFit      = clamp(1 - max(0, |BPM - 区间中心| - 半宽) / 55)   // 区间内满分
ValenceFit  = 1 - |歌曲valence - 目标valence|
ArousalFit  = 1 - |歌曲arousal - 目标arousal|

Penalty     = 0.40 · (近期播过，按时间衰减)  +  0.06 · min(2, 同艺人次数)
Bonus       = 0.03（本会话没播过的曲子）
```

在线曲目没有真实的 BPM/情感元数据，因此用当前情绪的画像值做**先验估计**并标记 `estimated`，
最终得分再乘 **0.90 的不确定性折扣**——不让"猜的数据"压过有真实元数据的本地曲目。

在线曲目的 `TagSim` 用**搜索相关性排名**代替标签矩阵（`0.88 - rank × 0.025`，下限 0.55）：
搜索引擎排得越靠前，说明和情绪关键词越贴题。这样在线结果才有梯度，不会全部同分。

### 4.4 多样性重排（MMR）

单纯按分数排序，前几首会高度同质（尤其 BPM 接近的曲子）。所以对排序结果再做一次
**最大边际相关（MMR）**重排：

```
选择标准 = score - λ · max(与已选曲目的相似度)      λ = 0.28

相似度(a,b) = 0.45·|ΔBPM|/70 + 0.30·|Δvalence| + 0.25·|Δarousal|
```

每次从候选池里挑"扣掉同质惩罚后最优"的一首，保证前几首在节奏和情感色彩上有区分。

### 4.5 可解释性

每首推荐结果都带 `reasons` 数组，直接显示在列表里，例如：

> 情绪标签完全命中「开心」· 节奏 124 BPM 落在开心的理想区间 108–134 · 亮度 0.92 匹配当前情绪基调

答辩时可以把 `recommendations[i].parts` 打印出来，看到 `tag / bpm / val / aro / penalty / bonus`
每一项的具体贡献。

## 五、曲库与在线接口

### 5.1 本地曲库（9 首）

`data/songs.json` 中每首歌都有**人工标注的真实元数据**：

```json
{
  "id": "happy-sunrise",
  "title": "That Perfect Song",
  "emotion": "happy",
  "bpm": 124,
  "valence": 0.92,
  "arousal": 0.78,
  "file": "audio/happy-sunrise.mp3"
}
```

标注覆盖 9 种用途：happy / sad / angry / fearful / disgusted / surprised / neutral / romantic / focused，
保证任何情绪都有对应曲目，且离线可用。

> 音频来自 **Audius** 平台的独立音乐人作品，仅用于课程学习演示，请勿商用。版权归各音乐人所有。

### 5.2 在线接口

| 接口 | 用途 | 是否需 Key | 备注 |
|---|---|---|---|
| iTunes Search API | 全球曲库元数据 + 30 秒官方试听 | 不需要 | 返回 `Access-Control-Allow-Origin: *`，浏览器可直连 |
| Audius API | 独立音乐人完整曲目，可直接流播 | 不需要 | 搜索 + `/stream` 302 到音频 CDN |

两者都支持 CORS，**不需要后端代理**。任一接口失败都不影响另一个（`Promise.allSettled` 思路，逐个容错），
失败信息会显示在歌单上方。

### 5.3 推荐的加载顺序

先本地、后在线：

1. 情绪稳定后**立刻**用本地曲库排出一版歌单 → 界面马上有内容
2. 同时异步请求在线曲库，回来后**合并、跨源去重、重新排序**，静默替换

这样即使在线接口慢或超时，界面也不会空白卡住。

## 六、四种画面输入

| 方式 | 实现 | 识别节奏 |
|---|---|---|
| 摄像头 | `getUserMedia` → `<video>` → 逐帧推理 | 约 200 ms/帧 |
| 本地图片 | `FileReader` → `<img>` → 单图推理 | 首次立即 + 1.5 s 低频复检 |
| 本地视频 | `URL.createObjectURL` → `<video>` 播放中推理 | 约 200 ms/帧 |
| 拍照定格 | 当前摄像头帧画到 canvas（**翻回非镜像**）→ 转图片模式 | 同本地图片 |

摄像头画面做了 `scaleX(-1)` 镜像（符合照镜子直觉），所以**人脸框的 canvas 也要一起镜像**，
否则框会左右反向。这条在 CSS 里单独处理了。

## 七、已知限制

1. **摄像头需要 localhost 或 https**，`file://` 下浏览器会直接拒绝（页面会给出提示）。
2. **弱光、侧脸、大遮挡**下检测会失败或概率分散，属 TinyFaceDetector 的固有局限；
   换成 `SSD Mobilenet` 精度更高但更慢，可按需替换。
3. **无 GPU 的机器**单帧推理约 2–3 秒；正常浏览器走 WebGL 后端约 100–300 ms。
4. 在线曲目的 BPM / 情感维度是**估算值**，不是真实分析结果，评分已做折扣处理。
5. iTunes 只提供 **30 秒试听**片段；Audius 是完整曲目但依赖网络。

## 八、开发过程中修掉的坑

留档，方便复盘：

| 问题 | 现象 | 原因与修复 |
|---|---|---|
| 单帧识别不生效 | 明明 happy 0.88，却报 neutral、置信度 3% | 单图走了迟滞锁定，被上一帧的标签拖住 → 单帧模式跳过迟滞，直接取 argmax |
| 推荐永不刷新 | 情绪变了，歌单一直不变 | 检测每 200 ms 一帧，每帧都 `clearTimeout` 重置 900 ms 计时器 → 记录 `pendingRecoEmotion`，排队中不重复重置 |
| 所有元素引用为 null | 上传图片抛 `Cannot read properties of null`，检测循环空转 | 模板 `ref="video"` 与 setup 返回的 `videoEl` 名字不一致 → 四处 ref 统一改名 |
| 同一首歌重复出现 | 本地与在线各来一份 | 合并时按「歌名+艺人」跨源去重，优先保留本地完整版 |
| 匹配分 103 分 | 分数超过 100 | 探索加分把总分顶过 1.0 → 返回前 `clamp` 到 [0,1] |
| 浮层显示函数源码 | 页面底部出现一段 JS 代码 | `v-if="toast"` 判断的是函数本身（永远为真）→ 改用 `toastMsg` |
| 误选画面边缘的脸 | 框住被裁掉半张的通缉犯脸 | `detectSingleFace` 只取最高置信度 → 改 `detectAllFaces` + 面积×中心度重挑主角 |
